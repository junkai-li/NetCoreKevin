- 路由模式：使用 createWebHistory（HTML5 History），便于 SEO 和分享链接。
- 基础路由：包含 / 重定向到 /login；/login 登录页；/home 作为带子路由的主布局。

### 浏览模式切换功能
**新增功能** 系统支持两种浏览模式：单页面模式和标签页模式，用户可通过顶部导航栏的"浏览模式"下拉菜单进行切换。

#### 单页面模式（SPA内部标签页）
- 所有页面在同一个浏览器标签页内通过内部标签页组件切换
- 使用 routeComponentMap 将路由key映射到对应组件
- 支持标签页的打开、关闭、刷新、多标签页管理
- 通过 openTabs 数组管理当前打开的标签页状态
- 使用 activeTabKey 标识当前激活的标签页

#### 标签页模式（新浏览器标签页打开）
- 点击菜单项时在新浏览器标签页中打开对应页面
- 使用 window.open() 方法打开新窗口
- 每个页面独立运行，互不影响
- 适合需要长时间运行的任务或需要独立会话的场景

#### 状态管理与持久化
- pageMode 状态存储在 localStorage 中，键名为 'page-mode'
- 默认值为 'tab'（标签页模式）
- 页面加载时自动读取并恢复用户的浏览模式选择
- 模式切换时自动调整界面行为和路由处理方式

```mermaid

CheckMode --> |single| SingleMode["单页面模式"]
CheckMode --> |tab| TabMode["标签页模式"]
```

### 标签页管理系统
**新增功能** 单页面模式下提供完整的标签页管理功能：

#### 标签页生命周期管理
- openTab(): 打开新标签页，避免重复打开相同页面
- closeTab(): 关闭指定标签页，智能处理当前激活标签的切换
- refreshTab(): 刷新指定标签页内容
- closeOtherTabs(): 关闭其他标签页，保留当前标签
- closeAllTabs(): 关闭所有可关闭的标签页

#### 组件动态渲染
- routeComponentMap: 路由key到Vue组件的映射表
- getComponentByKey(): 根据key动态获取对应组件
- getComponentProps(): 为组件传递必要的props参数
- v-if="activeTab": 只渲染当前激活的标签页内容

#### 路由同步机制
- routePathMap: 路由key到URL路径的映射
- getRoutePath(): 根据key获取对应的路由路径
- getRouteKey(): 反向映射，从路径获取菜单key
- 确保标签页状态与浏览器地址栏保持一致

### 路由参数传递、查询字符串与历史记录
- 参数传递：当前路由多为路径型参数（如 /home/user/list），可通过 router.push 的路径字符串或对象形式传递 params/query。

- **浏览模式影响**：标签页模式下使用 window.open() 打开新窗口，不改变当前页面的历史记录。

### 路由跳转最佳实践
- 统一使用命名路由与 params/query 传递参数，避免硬编码路径拼接。
- 对受保护路由统一通过 meta.requiresAuth 与 beforeEach 守卫控制。
- **菜单与路由解耦**：菜单 key 与路由 path 通过 routePathMap 映射表关联，便于扩展与维护。
- 避免重复跳转：在菜单点击前判断当前激活路由，防止无意义刷新。
- **浏览模式适配**：根据 pageMode 状态选择合适的跳转方式（router.push vs window.open）。

### 错误处理机制
- 路由层：beforeEach 中处理未登录跳转与已登录访问登录页的重定向。
- HTTP 层：http.js 在响应拦截器中统一处理 401/403/400/500，并在 401 时清理本地缓存并重定向到 /login，附带 redirect 参数以便登录后回跳。
- 页面层：登录失败与网络异常通过 message 提示用户。

## 性能考虑
- 首屏优化：将路由组件改为懒加载，减少初始包体大小。
- 路由复用：合理使用 keep-alive 缓存高频切换的页面，避免重复渲染。
- 权限预取：在登录成功后预取权限并缓存，减少后续重复请求。
- 路由守卫轻量化：避免在 beforeEach 中进行耗时操作，保持跳转流畅。
- **标签页性能优化**：单页面模式下只渲染当前激活的标签页，避免同时加载多个组件。
- **内存管理**：及时清理不需要的标签页，避免内存泄漏。

## 故障排查指南
- 无法进入受保护页面：检查 localStorage 中是否存在 token；确认路由 meta.requiresAuth 是否正确设置；查看 beforeEach 是否被意外中断。
- 登录后仍跳转回登录页：检查 http.js 的 401 处理逻辑；确认后端是否返回 newtoken；确认 getUserPermissions 是否成功执行。
- 菜单不显示：检查 UserPermissions 是否已正确写入 localStorage；确认 hasPermission 逻辑与菜单 permission 字段匹配。
- 404 页面未生效：确认是否在路由末尾添加了 catch-all 路由；确认服务端是否将未知路径回退到 index.html。
- **浏览模式切换无效**：检查 localStorage 中 'page-mode' 的值；确认 switchPageMode 函数是否正确执行；验证页面模式状态是否正确更新。
- **标签页功能异常**：检查 openTabs 数组状态；确认 routeComponentMap 中组件映射是否正确；验证 activeTabKey 是否与当前路由一致。
