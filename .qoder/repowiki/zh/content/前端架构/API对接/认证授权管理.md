## 简介
本文件面向后端认证授权子系统，覆盖登录流程、Token生成与刷新、权限校验（路由守卫与接口级）、用户信息缓存以及登出清理策略。文档以代码为依据，提供流程图与时序图，帮助读者快速理解并落地集成。

**更新** 系统现已支持基于Redis的分布式令牌版本控制和完整的登出功能，包括即时令牌黑名单和分布式令牌撤销机制。同时增强了账户安全机制，支持账户锁定和密码复杂度验证。

## 项目结构
认证授权相关能力分布在以下模块：
- Web层控制器：对外暴露登录、短信登录、登出等接口
- 应用服务：实现登录业务、租户校验、Token签发入口
- JWT模块：负责访问令牌签发与刷新、刷新令牌缓存、令牌版本控制
- 权限模块：基于自定义鉴权策略进行接口级权限控制，支持自动续发新Token
- 统一响应处理器：将未认证/无权限场景返回为统一的JSON格式

### 登录流程（用户名/密码）
- 控制器接收登录参数，委托应用服务完成登录与租户校验
- 应用服务验证租户存在且有效，检查IP是否被锁定，调用用户服务完成认证
- 用户服务进行账户锁定检查、密码验证、失败计数管理
- 成功后使用JWT服务签发访问令牌，并将刷新令牌写入缓存
- **新增** 令牌版本控制：每次签发令牌时获取当前用户版本号，确保令牌安全性
- 前端保存accessToken用于后续请求；同时可保存refresh token以便刷新

### Token管理机制（本地存储、自动刷新、过期处理）
- 访问令牌：包含用户标识、是否超级管理员、姓名、创建时间、租户ID、**令牌版本号**等声明；过期时间由配置决定
- 刷新令牌：以访问令牌为键，缓存刷新信息（过期时间、用户信息、**令牌版本号**），用于换发新访问令牌
- 自动续发：当请求中JWT即将过期（剩余不足20分钟）时，鉴权阶段自动调用刷新接口，并在响应头中回传新令牌
- **新增** 令牌版本控制：每个用户有独立的令牌版本号存储在Redis中，改密/封禁时版本号自增，旧令牌立即失效
- **新增** 用户令牌索引：维护用户所有活跃刷新令牌的索引，便于批量吊销和管理
- 前端建议：
  - 将accessToken存入内存或安全存储，每次请求附加到Authorization头
  - 监听响应头NewToken，更新本地令牌
  - 若收到401/403，引导重新登录


### 登出处理逻辑（清理本地数据与重置应用状态）
- **新增** 服务端登出接口：`POST /api/authorize/Logout`
- 登出流程：
  1. 将当前access token加入Redis黑名单（TTL与令牌剩余有效期一致）
  2. 删除对应的刷新令牌缓存
  3. 从用户令牌索引中移除该令牌记录
- 黑名单机制：被拉黑的token在有效期内无法再次使用，到期后自动清理
- 分布式令牌撤销：支持批量吊销用户所有令牌（改密/封禁/删除用户时调用）
- 客户端侧建议：
  - 清除本地存储的accessToken与refresh token
  - 清空用户信息缓存（如权限列表、用户资料）
  - 跳转至登录页并重置应用状态

```mermaid
flowchart TD
Start(["登出请求"]) --> ExtractToken["提取Authorization头中的token"]
ExtractToken --> Blacklist["加入Redis黑名单(TTL=剩余有效期)"]
Blacklist --> RemoveRefresh["删除刷新令牌缓存"]
RemoveRefresh --> RemoveIndex["从用户令牌索引移除"]
RemoveIndex --> Success["返回登出成功"]
```

### 账户锁定与安全机制
- **新增** 账户锁定机制：
  - 连续密码错误达到阈值后自动锁定账户
  - 锁定时长可配置，默认15分钟
  - 锁定期间拒绝所有登录尝试
- **新增** IP地址锁定机制：
  - 同一IP连续登录失败达到阈值后锁定IP
  - 锁定时长可配置，默认30分钟
  - 防止暴力破解攻击
- **新增** 密码复杂度验证：
  - 支持正则表达式验证密码强度
  - 默认要求至少三种字符类型组合
  - 可配置自定义复杂度规则
- **新增** 失败计数管理：
  - 记录用户登录失败次数
  - 达到阈值后设置账户锁定截止时间
  - 登录成功后重置失败计数

## 故障排查指南
- 401 未认证
  - 检查请求是否携带正确的Authorization头
  - 确认JWT未过期；若即将过期，关注响应头NewToken是否被正确更新
  - 检查令牌版本是否匹配（改密/封禁后旧令牌会失效）
  - 查看统一响应处理器返回的JSON结构
- 403 无权限
  - 检查当前用户是否拥有对应area/module/action权限
  - 确认控制器/动作未误标为公开或跳过鉴权
- 刷新失败
  - 检查缓存中是否存在有效的刷新令牌
  - 确认刷新令牌版本号与Redis中最新版本一致
  - 确认刷新令牌已被消费（一次性策略）
- 登出失败
  - 检查Redis连接是否正常
  - 确认黑名单机制是否正常工作
  - 验证用户令牌索引是否正确维护
- 账户锁定问题
  - 检查账户锁定截止时间是否在未来
  - 确认失败计数是否超过阈值
  - 验证锁定时长配置是否正确
- IP锁定问题
  - 检查IP锁定缓存是否存在
  - 确认IP失败计数是否超过阈值
  - 验证分布式锁是否正常工作

## 附录：API调用示例与错误处理

- 登录（用户名/密码）
  - 方法：POST
  - 路径：/api/authorize/GetToken
  - 请求体：dtoLogin（用户名、密码、租户ID）
  - 成功响应：字符串（accessToken）
  - 失败响应：统一JSON（401/403）

- 发送短信验证码
  - 方法：POST
  - 路径：/api/authorize/SendSmsVerifyPhone
  - 请求体：dtoKeyValue（key=手机号）
  - 成功响应：布尔值

- 短信登录
  - 方法：POST
  - 路径：/api/authorize/GetTokenBySms
  - 请求体：dtoKeyValue（key=手机号，value=验证码）
  - 成功响应：字符串（accessToken）
  - 失败响应：统一JSON（401/403）

- **新增** 登出
  - 方法：POST
  - 路径：/api/authorize/Logout
  - 请求头：Authorization: Bearer <accessToken>
  - 成功响应：布尔值（true表示登出成功）
  - 失败响应：布尔值（false表示登出失败）

- 自动续发新令牌
  - 触发条件：JWT剩余有效期小于20分钟
  - 响应头：NewToken（新accessToken）
  - 客户端行为：更新本地accessToken

- 错误处理建议
  - 捕获401：提示重新登录，并清理本地令牌
  - 捕获403：提示权限不足，联系管理员
  - 网络异常：重试与降级策略
  - **新增** 令牌版本不匹配：提示用户重新登录，因为可能发生了密码修改或账户被封禁
  - **新增** 账户锁定：提示用户稍后再试，显示锁定剩余时间
  - **新增** IP锁定：提示IP被锁定，联系管理员解锁
