### 请求队列控制（QueueLimitFilter）
- **全新功能**：异步 Action 过滤器
  - 完全重写为 IAsyncActionFilter，消除了线程饥饿问题。
  - 支持两种工作模式：
    - **阻塞模式**（IsBlock=true）：无法立即获取锁时立即返回友好提示
    - **排队模式**（IsBlock=false）：异步等待锁，单次等待 60 秒，超时继续下一轮等待
  - 使用分布式锁确保同一 Action 同一时刻只放行一个请求。
  - 支持按 Action 名称和可选 Token 区分请求，使用 MD5 哈希生成锁键。
- 线程安全设计
  - 使用 await 关键字确保异步操作不会阻塞线程池线程。
  - 在 finally 块中确保锁的正确释放。
  - 捕获 OperationCanceledException 处理客户端断开连接的情况。
- 使用示例
  ```csharp
  [HttpPost("SensitiveOperation")]
  [QueueLimitFilter(IsBlock = true, UseToken = true)]
  public async Task<IActionResult> SensitiveOperation()
  {
      // 业务逻辑
  }
  ```

### 分布式 ID 生成（SnowflakeIdService）
- **修复**：高并发重复 ID 生成问题
  - 使用静态共享状态确保多线程环境下的唯一性。
  - 所有实例共享相同的 lastTimestamp、sequence 和 syncRoot 锁对象。
  - 避免了多个实例各自持有独立状态导致的重复 ID 问题。
- 配置管理
  - 支持通过 IOptionsMonitor<SnowflakeIdSetting> 动态配置机器标识和数据中心标识。
  - 提供 SetFallbackSetting 方法用于无 DI 上下文时的兜底配置。
  - 启动时自动同步配置到静态快照，确保所有实例配置一致。
- 算法实现
  - 标准雪花算法：时间戳 + 数据中心ID + 节点ID + 序列号。
  - 毫秒级时间戳，每毫秒最多生成 4096 个唯一 ID（12位序列号）。
  - 时钟回拨保护机制，抛出异常防止时间回退导致的 ID 冲突。

### 数据库连接池与 EF Core 查询优化
- 连接池
  - 使用 AddDbContextPool 配置 DbContext 池大小，减少频繁创建销毁开销。
- 默认索引字段
  - 通过 DBDefaultHasIndexFields 配置常用字段自动添加索引，提升查询性能。
- 模型与查询优化
  - 关闭外键级联删除，避免意外级联更新带来的性能损耗。
  - 使用调试拦截器记录 SQL，便于定位慢查询。
  - 按需开启懒加载代理（当前注释），避免 N+1 问题。
- 批量与事务
  - SaveChangesWithSaveLog 用于审计日志；业务层可使用批量插入/更新（如 EF Core 扩展）减少往返次数。
- 多租户与乐观并发

## 性能注意事项
- 启动优化
  - 最小化启动时反射与初始化逻辑；按需启用模块（如 MCP、AI 相关服务）。
  - 合理设置 GC 堆硬限制，避免 OOM。
- 中间件顺序
  - 压缩、HSTS、CORS、静态文件应在认证之前；认证/授权在路由之后。
- 缓存策略
  - 热点数据优先使用内存缓存；跨进程共享使用 Redis；注意 TTL 与键设计。
  - **新增**：使用 GetObjectOrDefault<T>() 方法处理可能不存在的缓存项，提高代码健壮性。
- 请求队列控制
  - **全新**：对于敏感操作使用 QueueLimitFilter 防止重复请求和并发问题。
  - 选择合适的模式：阻塞模式适合需要立即响应的场景，排队模式适合可以等待的场景。
  - 合理设置 UseToken 参数，按用户或会话隔离请求。
- 分布式 ID 生成
  - **修复**：SnowflakeIdService 已修复高并发重复 ID 问题，确保全局唯一性。
  - 正确配置 MachineId 和 DataCenterId，避免不同实例间的 ID 冲突。
- 数据库优化
  - 为高频查询字段添加索引；使用分页与投影减少数据传输；避免 N+1 查询。
- API 响应
  - 启用响应压缩；控制 JSON 深度与缩进；统一响应结构便于前端处理。
- 异步与并发
  - 全面使用异步；避免同步阻塞；合理配置连接超时与保活间隔。
  - **新增**：QueueLimitFilter 的异步设计避免了线程饥饿问题。
- **新增**：分布式锁优化
  - 利用2小时自动过期机制防止锁累积；监控锁的使用情况；合理设置业务逻辑的执行时间。

## 故障排查指南
- 缓存异常
  - 检查 ICacheService 注入是否正确；确认 Redis 连接串与权限；查看 CacheDataFilter 的 TTL 与键生成逻辑。
  - **新增**：检查智能过期处理是否正常工作；验证 GetObjectOrDefault<T>() 方法的返回值。
- 数据库连接失败
  - 检查 appsettings.json 中 dbConnection 与 DBDefaultHasIndexFields；确认 MySQL 服务状态与权限。
- SignalR 连接问题
  - 检查 SignalrRdisSetting 配置；确认 Redis 端口、密码、默认库与配置通道。
- Hangfire 任务失败
  - 检查 HangfireRedisSetting 与用户凭据；查看仪表板任务日志。
- **新增**：分布式锁问题
  - 检查 Redis 连接状态；确认2小时过期配置是否正确；监控锁的获取和释放情况。
  - 如果锁被永久占用，检查是否有异常任务未正确释放锁。
- **新增**：QueueLimitFilter 问题
  - 检查分布式锁提供程序是否正确注入；确认 IsBlock 和 UseToken 配置是否符合预期。
  - 如果请求长时间等待，检查排队模式的超时配置和业务逻辑执行时间。
- **新增**：SnowflakeIdService 问题
  - 检查 MachineId 和 DataCenterId 配置是否唯一；确认没有重复的实例配置。
  - 如果出现重复 ID，检查是否有多个实例使用了相同的配置。
