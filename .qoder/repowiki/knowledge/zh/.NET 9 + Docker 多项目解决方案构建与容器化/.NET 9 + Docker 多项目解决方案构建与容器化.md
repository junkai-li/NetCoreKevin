## 1. 构建系统与工具链

- **语言/框架**: .NET 9 (`net9.0` TargetFramework)，ASP.NET Core Web API。
- **解决方案管理**: 根目录 `NetCoreKevin.sln` 是唯一的 Visual Studio Solution，使用 VS 17.13 格式，定义四个顶层 Solution Folder：`App`（业务应用）、`Kevin`（核心框架模块）、`Test`（测试套件）、`Module`（可复用模块集合）。
- **包管理**: 采用传统的 `.csproj` + NuGet PackageReference 方式，无 `Directory.Packages.props` 或 Central Package Management；版本散落在各项目文件中（如 EFCore 9.0.11、SignalR 10.0.0 等）。
- **前端构建**: Vue 3 单页应用位于 `vue/kevin.web.vue/`，通过 `@vue/cli-service`（v5）构建，提供 `serve` / `build` / `lint` 脚本，并通过 `.env.development`、`.env.pre` 等多环境配置文件区分构建模式。
- **容器化**: 仅后端 WebApi 提供 Dockerfile（`App/WebApi/Dockerfile`），基于 `mcr.microsoft.com/dotnet/aspnet:9.0` 与 `dotnet/sdk:9.0` 的多阶段构建，最终镜像暴露端口 8080 并设置 `ASPNETCORE_URLS=http://+:8080`。`docker-compose.yml` 存在但为空文件，未编排依赖服务。
- **CI/CD**: 仓库中未发现 GitHub Actions、GitLab CI、Jenkinsfile、Azure Pipelines 等 CI 配置；发布流程主要依赖 Visual Studio 的 `Properties/PublishProfiles/FolderProfile.pubxml` 进行文件夹发布。

## 3. 架构与约定

### 3.1 分层与模块化
- 每个业务域（`App`、`Kevin`）均遵循 Domain → Application → RepositorieRps → WebApi 的分层结构，各层独立 `.csproj`，通过 `ProjectReference` 单向引用。
- 横切能力被拆分为独立 NuGet 风格的模块（`Kevin/kevin.Module/*`），如缓存、权限、SignalR、RabbitMQ、Consul、Hangfire、RAG、AI Agent Framework 等，由 `Kevin.ALL.Module` 聚合引用后对外发布。
- 测试工程按 xUnit 组织，`Testing.Shared` 提供公共测试基类与特性（如 `AutoFakeItEasyAttribute`、`PriorityOrderer`），单元测试与集成测试分离。

### 3.2 构建产物与输出
- WebApi 在 Release 模式下关闭调试符号（`DebugType=none`、`DebugSymbols=false`），并生成 XML 文档（`DocumentationFile=App.WebApi.xml`）。
- Docker 构建阶段先 `COPY *.csproj` 再 `dotnet restore`，利用 Docker 层缓存加速增量构建；发布阶段使用 `/p:UseAppHost=false` 生成自包含 DLL 部署。
- 前端通过 `vue-cli-service build` 产出静态资源到 `dist/`，由 Nginx/IIS 托管（当前仓库未包含前端容器化配置）。

### 3.3 环境与配置
- 通过 `appsettings.{Environment}.json` 与 `launchSettings.json` 区分开发/测试环境。
- 日志按环境拆分：`LogConfigs/log4.config`（默认）、`log4.Development.config`、`log4.Test.config`。
- Docker 镜像强制监听 8080 端口，便于容器编排。

## 4. 约定与约束

- **目标框架统一**: 所有 .NET 项目均以 `net9.0` 为目标框架，保证编译一致性。
- **Docker 构建上下文**: `App.WebApi.csproj` 将 `DockerfileContext` 指向仓库根，使 Docker 能访问整个解决方案树。
- **EF Core 迁移**: 数据库变更通过 `Kevin.EntityFrameworkCore/Migrations/` 下的时间戳命名迁移文件管理（如 `20260731075430_初始化字段.cs`），配合 `KevinDbContextModelSnapshot.cs` 跟踪模型快照。
- **模块注册**: 各模块通过 `ServiceCollectionExtensions` + `ApplicationBuilderExtensions` 扩展方法实现“零侵入”注册，由聚合模块 `Kevin.ALL.Module` 统一引入。
- **发布策略**: 使用 Visual Studio Publish Profile（`FolderProfile.pubxml`）进行文件夹发布，未启用自包含发布；NuGet 包通过 `Kevin.ALL.Module.csproj` 的 `<Package*>` 元数据发布。
- **前端构建模式**: 通过 `--mode development` / `--mode pre` 切换不同环境的构建，对应 `.env.development`、`.env.pre` 配置文件。
- **无全局 CI**: 仓库未包含自动化流水线，本地构建命令为 `dotnet build NetCoreKevin.sln`、`dotnet test`、`docker build -f App/WebApi/Dockerfile -t netcore-kevin .`。

## 5. 缺失项说明

- 没有 Makefile、`build*.sh`、`build.ps1` 等跨平台构建脚本。
- `docker-compose.yml` 为空，未编排 MySQL、Redis、RabbitMQ、Consul 等依赖服务。
- 未发现任何 CI/CD 配置文件（`.github/workflows`、`.gitlab-ci.yml`、`azure-pipelines.yml`、`Jenkinsfile` 等均不存在）。
- 前端未提供 Docker 镜像构建配置，仅输出静态文件。
