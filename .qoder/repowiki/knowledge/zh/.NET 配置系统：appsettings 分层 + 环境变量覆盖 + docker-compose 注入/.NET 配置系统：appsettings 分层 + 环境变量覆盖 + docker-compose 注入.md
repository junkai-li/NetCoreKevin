## 1. 使用的框架与工具

- 基于 ASP.NET Core 内置的 `Microsoft.Extensions.Configuration`，通过 `WebApplication.CreateBuilder(args)` 自动加载 `appsettings.json`、`appsettings.{Environment}.json`。
- 使用 `IConfiguration` / `IConfigurationSection` 按命名空间分组读取（如 `ConnectionStrings`、`Jwt`、`HangfireSetting`、`RabbitMQ`、`SignalrRdisSetting`、`ConsulSetting`、`TencentCloudSMS`、`AliCloudFileStorage`、`QdrantClientSetting`、`OpenAICompatibleSetting` 等）。
- 通过 `docker-compose.yml` 以 `Key__SubKey` 形式向容器进程注入环境变量，由 .NET 配置系统自动映射为嵌套 JSON 节点（例如 `ConnectionStrings__dbConnection` → `ConnectionStrings:dbConnection`）。
- 使用 `.env.example` 作为 docker-compose 变量模板，配合 `${VAR:-default}` 语法提供默认值。

## 2. 关键文件

- `App/WebApi/Program.cs` — 应用启动入口，负责设置环境、初始化日志、调用 `builder.Services.ConfigureServices(builder.Configuration)`、根据 `DB_AUTO_MIGRATE` 执行 EF Core 迁移、调用 `app.UseKevin(builder.Configuration)`。
- `App/WebApi/appsettings.json` — 生产/默认配置，包含连接串、JWT、Redis、RabbitMQ、Consul、云存储、AI 模型、OpenAI 兼容接口等全部运行时参数。
- `App/WebApi/appsettings.Development.json` / `appsettings.Test.json` — 开发/测试环境覆盖文件，结构与默认文件一致，仅覆盖差异项。
- `App/WebApiMcp/appsettings.json`、`App/WebApiMcp/appsettings.Development.json`、`App/WebApiMcp/appsettings.Test.json` — MCP 子应用的同名配置结构。
- `Kevin/kevin.Module/Kevin.Common/Helper/EnvironmentConfigHelper.cs` — 定义 `Development` / `Test` / `Formal` 常量与环境字典，并提供 `GetEnvironment()` 和 `SetEnvironment(env)`。
- `Kevin/kevin.Module/Kevin.log4Net/EnvironmentConfigHelper.cs` — log4net 模块内对 `NETCORE_ENVIRONMENT` / `ASPNETCORE_ENVIRONMENT` 的读取封装。
- `docker-compose.yml` — 所有服务的环境变量来源，将 MySQL/Redis/Qdrant/RabbitMQ 的连接信息以配置键的形式注入 api 容器。
- `.env.example` — docker-compose 变量示例（端口、密码、`DB_AUTO_MIGRATE`、`VUE_APP_API_BASE_URL`、镜像源等）。

## 3. 架构与约定

### 3.1 环境分层

项目定义了三种运行环境：
- `Development` → 加载 `appsettings.Development.json`
- `Test` → 加载 `appsettings.Test.json`
- 空字符串（`Formal`）→ 加载 `appsettings.json`

`EnvironmentConfigHelper.SetEnvironment` 在 `Program.Main` 中首先被调用，把读到的环境变量写回 `NETCORE_ENVIRONMENT` 与 `ASPNETCORE_ENVIRONMENT`，从而让 ASP.NET Core 的配置系统选择对应的 `appsettings.*.json`。该 helper 同时打印当前环境描述。

### 3.2 配置优先级（从低到高）

1. `appsettings.json`（默认）
2. `appsettings.{Environment}.json`（由 `ASPNETCORE_ENVIRONMENT` 决定）
3. 进程环境变量（包括 docker-compose 注入的 `Key__SubKey` 形式的变量），会覆盖同名 JSON 节点
4. 代码中显式设置的值（如 `DB_AUTO_MIGRATE` 在 `Program.cs` 中直接 `Environment.GetEnvironmentVariable` 读取）

### 3.3 配置分组约定

配置按功能域组织为扁平的顶层 key，每个域对应一个 POCO 或 `IConfigurationSection`：
- `ConnectionStrings` — 数据库与 Redis 连接串
- `Jwt` — JWT Key/Issuer/Audience/过期时间
- `HangfireSetting` / `HangfireRedisSetting` — Hangfire 任务队列
- `SignalrRdisSetting` — SignalR 的 Redis 背板
- `CorsSetting` / `ConsulSetting` — CORS 与服务发现
- `TencentCloudSMS` / `AliCloudSMS` / `TencentCloudFileStorage` / `AliCloudFileStorage` / `QiniuCloudFileStorage` — 第三方云服务凭据
- `RabbitMQ` — 消息队列
- `EmailSetting` / `SnowflakeIdSetting` / `CodeGeneratorSetting` / `QdrantClientSetting` / `OllamaApiSetting` / `AESInfo` / `DingDingMsgInfo` / `DingDingOAApiInfo` / `AliRerankApiSetting` / `AliyunAsr` / `DoubaoSearchApiSetting` / `HttpInterToMcpService` / `SkillToolSecuritySetting` / `AIChatStorageSetting` / `AITokenQuotaSetting` / `Modality` / `ImageGeneration` / `OpenAICompatibleSetting` — 各业务子系统开关与参数

### 3.4 容器化配置

`docker-compose.yml` 中 api 服务的 `environment` 段大量使用 `Key__SubKey` 语法（双下划线分隔层级），例如：
```
ConnectionStrings__dbConnection: "server=mysql;port=3306;database=${MYSQL_DATABASE:-kevin_app};..."
QdrantClientSetting__Url: qdrant
DB_AUTO_MIGRATE: ${DB_AUTO_MIGRATE:-true}
RabbitMQ__HostName: ${RABBITMQ_HOST:-rabbitmq}
```
这些变量来自同目录的 `.env`（由 `.env.example` 复制而来），未设置时使用 `:-default` 语法提供默认值。

### 3.5 特殊运行时开关

- `DB_AUTO_MIGRATE`：在 `Program.cs` 中直接通过 `Environment.GetEnvironmentVariable` 读取，控制是否在启动阶段执行 EF Core 迁移（无迁移文件时回退到 `EnsureCreated`，有失败重试最多 10 次）。
- `GCHeapHardLimit`：硬编码为 2GB，注释说明是 AI 应用需要更多内存。
- `ThreadPool.SetMinThreads(200, ...)`：容器环境下提升线程池下限以避免同步阻塞导致的积压。

## 4. 约定与约束

- **环境标识只允许 `Development`、`Test` 或空字符串**：`EnvironmentConfigHelper.EnvironmentDictionary` 仅注册这三个键，传入其他值会在 `ConsoleHelper.PrintFrameworkName` 处抛异常；`SetEnvironment(null)` 会被归一化为 `Formal`（空字符串）。
- **容器部署不设置 `ASPNETCORE_ENVIRONMENT=Production`**：`docker-compose.yml` 明确注释“不要设置 ASPNETCORE_ENVIRONMENT=Production”，因为框架的 helper 只识别 Development/Test/空值，空值即「正式环境」。
- **敏感配置（连接串、密钥、API Key）应通过环境变量注入**：`docker-compose.yml` 中所有连接串都使用 `${MYSQL_ROOT_PASSWORD:-admin123}` 等形式，避免硬编码到 appsettings 中。
- **配置键名必须与 `IConfiguration` 绑定路径一致**：新增配置项需要在 `appsettings.json` 中声明并在使用方通过 `Configuration.GetSection("XxxSetting")` 或 `Configuration.Get<T>()` 读取，否则无法被环境变量覆盖。
- **`.env.example` 是所有 docker-compose 变量的单一文档**：注释说明“所有变量都有默认值，不创建 .env 也能直接启动”。
- **log4net 配置文件按环境区分**：`App/WebApi/LogConfigs/log4.config`、`log4.Development.config`、`log4.Test.config`，由 `LoggingBuilderExtensions` 根据环境加载。
- **前端构建参数通过 Nginx 反向代理同源部署**：`.env.example` 中 `VUE_APP_API_BASE_URL` 留空表示同源部署，Nginx 把 `/api`、`/KevinFlies` 转发给 api 容器，见 `docker-compose.yml` web 服务的构建参数说明。
