## 1. 使用的系统/方法

本仓库是一个 .NET 9 + Vue3 的混合工程，依赖管理由两套体系共同完成：

- **.NET 侧**：使用 Visual Studio Solution（`NetCoreKevin.sln`）统一编排 30+ 个 `.csproj` 项目；通过 `<ProjectReference>` 引用同仓内的 `App.*`、`Kevin.*`、`Test.*` 子项目，通过 `<PackageReference>` 引用 NuGet 公共源上的第三方库。目标框架统一为 `net9.0`。
- **前端侧**：Vue 工程位于 `vue/kevin.web.vue/`，使用 `package.json` 声明依赖，并通过本地 `node_modules/` 目录进行依赖安装和锁定（存在 `package-lock.json`）。

仓库中**没有**发现 `nuget.config`、私有 NuGet 源配置、`packages.lock.json`、`global.json`、`Directory.Packages.props`、`vendor/` 等集中式或锁定文件；也没有 Go 生态的 `go.mod`/`go.sum`。

## 3. 架构与约定

### 3.1 .NET 项目分层与依赖方向

Solution 将项目按业务边界划分为四个顶层分组：

- **App**：业务应用层（WebApi / Application / Domain / RepositorieRps / AppShare），面向具体租户或产品线。
- **Kevin**：核心框架与领域层（Domain / Application / RepositorieRps / EntityFrameworkCore / Share）。
- **Module**：可复用的横切能力模块（`kevin.Cache`、`kevin.Cap`、`kevin.Consul`、`kevin.FileStorage`、`kevin.Permission`、`kevin.RabbitMQ`、`kevin.SignalR`、`kevin.SMS`、`kevin.RAG`、`kevin.AI.AgentFramework`、`Kevin.log4Net`、`Kevin.Authentication.Jwt`、`Kevin.Hangfire`、`Kevin.Email`、`Kevin.CodeGenerator`、`Kevin.Cors`、`kevin.Ioc`、`kevin.DistributedLock`、`kevin.Domain.EventBus`、`kevin.SnowflakeId`、`Kevin.Versioning.Swagger`、`Kevin.Asr`、`Kevin.HttpApiClients`、`Kevin.Web.Basics`）。
- **Test**：单元测试与集成测试。

依赖方向遵循“上层依赖下层”的分层原则：`App.WebApi → App.Application → App.Domain → Kevin.*`，再由 `Kevin.ALL.Module` 作为聚合入口一次性引入所有 kevin 模块。

### 3.2 包版本管理策略

- **每个 `.csproj` 自行声明 `<PackageReference Include="..." Version="x.y.z" />`**，未使用 Central Package Management（无 `Directory.Packages.props`）。因此同一包在不同项目中可能出现重复声明（例如 `AngleSharp 1.7.1`、`log4net 3.3.2`、`SSH.NET 2026.0.0`、`System.Security.Cryptography.Xml 9.0.19` 在多个项目中重复出现）。
- 所有 .NET 项目统一 target `net9.0`，保证运行时一致性。
- `Kevin.ALL.Module.csproj` 设置了 `<Version>1.0.1</Version>` 和 `PackAsTool=True`，表明该聚合模块本身可作为 NuGet 包对外发布。
- 前端使用 `package.json` 中的 `^` 语义化版本范围（如 `ant-design-vue: ^4.2.6`、`axios: ^1.17.0`），配合 `package-lock.json` 锁定实际解析版本。

### 3.3 私有/内部依赖

- 仓库内不存在 `NuGet.Config`、`~/.nuget/NuGet/NuGet.Config`、`nuget.config` 等自定义源配置，也未发现 `PrivatePackages` 或 `GOPRIVATE` 类环境变量。
- 内部代码以 `ProjectReference` 形式共享，不通过私有 NuGet 源分发。
- 外部云服务密钥（如 Ollama API key、阿里云/腾讯云 AK/SK）通过 `appsettings.{Environment}.json` 配置文件注入，而非编译期常量。

### 3.4 构建与容器化中的依赖

- `App/WebApi/Dockerfile` 基于 .NET 9 SDK/Runtime 镜像构建，依赖由 `dotnet restore` 从公共 NuGet 源拉取。
- `docker-compose.yml` 编排了后端、数据库、缓存等基础设施，但依赖声明仍集中在各 `.csproj` 中。
- 前端 `vue/kevin.web.vue/` 通过 `npm install` 生成 `node_modules/`，该目录已在仓库中存在（体积较大）。

## 4. 约定与约束

| 约定 | 证据/范围 |
|---|---|
| 所有 .NET 项目统一 target `net9.0` | 所有被检查的 `.csproj` 均包含 `<TargetFramework>net9.0</TargetFramework>` |
| 内部模块通过 `ProjectReference` 耦合，不在 NuGet 上发布 | `NetCoreKevin.sln` 将所有 kevin 模块纳入同一 Solution，`Kevin.ALL.Module` 仅做聚合引用 |
| 第三方 NuGet 包在每个 `.csproj` 中显式声明版本号 | 未发现中央包管理文件，包版本分散在各项目文件中 |
| 前端依赖使用 `^` 语义化版本范围并由 `package-lock.json` 锁定 | `package.json` 中依赖项普遍带 `^`，且 `package-lock.json` 存在于仓库 |
| 构建产物不包含 `obj/`、`bin/`、`node_modules/` | `.gitignore` 排除了这些目录 |
| 调试/发布时关闭调试符号 | Release 配置中 `<DebugType>none</DebugType>`、`<DebugSymbols>false</DebugSymbols>` |
| 日志、权限、消息队列等横切能力以独立 kevin.* 模块提供 | `Kevin/kevin.Module/` 下每个功能一个独立 `.csproj`，由 `Kevin.ALL.Module` 聚合 |

## 5. 风险与改进点（观察性描述）

- 缺少 `Directory.Packages.props` 或 `packages.lock.json`，导致相同 NuGet 包在多个项目中重复声明版本，升级时需逐个修改。
- 前端 `node_modules/` 已提交至仓库，会显著增大 Git 仓库体积，通常建议将其加入 `.gitignore` 并在 CI 中执行 `npm ci`。
- 未发现统一的 NuGet 私有源或代理配置，若团队需要隔离外网访问，需补充 `nuget.config`。
