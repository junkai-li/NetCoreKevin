模块以经典四层架构拆分为独立 csproj 项目，形成单向依赖：WebApi → Application → Domain ← RepositorieRps，AppShare 作为跨层共享 DTO。
- WebApi（入口层）：Program.cs 通过 `WebApplication.CreateBuilder` 构建宿主，注册 `UseKevinLog4Net` 日志、`AddControllers`、全局异常处理、`UseKevin` 中间件，并通过扩展方法 `ConfigServies` 完成服务装配；同时启用 Kestrel HTTPS、设置 GCHeapHardLimit=2G、根据 `DB_AUTO_MIGRATE` 环境变量在启动时重试执行 EF Core 迁移；Controllers/v1、v2 下按版本号划分 API。
- Application（应用服务层）：Services/v1 下的 Service 继承 `BaseService`，实现 Domain 中定义的 `I*Service` 接口，通过构造函数注入仓储接口完成用例编排；ModuleInitializer 使用 `IocHelper.BatchAddScopeds<IService>` 批量注册。
- Domain（领域层）：Entities 定义实体（继承 `CUD_User`），Interfaces/Repositorie 与 Interfaces/Services 分别声明仓储与服务契约，作为应用与仓储之间的稳定边界；ModuleInitializer 仅输出初始化日志。
- RepositorieRps（仓储实现层）：Repositories/v1 中的 *Rp 继承通用 `Repository<T, TId>` 并实现对应接口，由 ModuleInitializer 通过 `IocHelper.BatchAddScopeds<IBaseRepository>` 批量注册。
- AppShare（共享 DTO 层）：Dtos/v1 存放跨层共享的数据传输对象。
- WebApiMcp（MCP 子服务）：独立的 ASP.NET Core 程序，通过 EnvironmentConfigHelper 切换环境配置，用于 HTTP→MCP 协议转换。
