## 1. 使用的系统/方法

本仓库采用两套并行的依赖管理体系：

- **.NET / C#**：使用 **NuGet**，并通过 **Central Package Management (CPM)**（即 `Directory.Packages.props`）集中声明所有第三方包的版本；前端 **Vue** 子项目使用 **npm**（`package.json` + `package-lock.json`）。
- 没有发现 vendoring、私有 NuGet 源或 `nuget.config` 配置——所有包均从公共 NuGet.org 拉取。

## 2. 关键文件

- `Directory.Packages.props`：整个 .NET 解决方案的单一 NuGet 包版本清单，包含约 100 个 `<PackageVersion>` 条目。
- `NetCoreKevin.sln`：Visual Studio 解决方案，聚合 App / Kevin / Test / Module 四大分组下的 ~35 个 `.csproj`。
- `vue/kevin.web.vue/package.json`：前端依赖声明（dependencies + devDependencies），配合 `package-lock.json` 锁定安装结果。
- 各 `.csproj` 中的 `<PackageReference Include="..." />` 仅写包名、不写版本号（由 CPM 注入）。

## 3. 架构与约定

### 3.1 .NET 中央包版本管理（CPM）

`Directory.Packages.props` 顶部显式启用两项设置：

```xml
<ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
<CentralPackageTransitivePinningEnabled>true</CentralPackageTransitivePinningEnabled>
```

- `ManagePackageVersionsCentrally=true`：所有 `PackageReference` 不得带版本号，版本统一在 `Directory.Packages.props` 中维护。
- `CentralPackageTransitivePinningEnabled=true`：**传递依赖也按此处版本对齐**，避免“传递依赖取最低版本导致的漏洞告警”。该注释是仓库内对这一决策的唯一说明。

这意味着新增 NuGet 包时，必须先在 `Directory.Packages.props` 中添加 `<PackageVersion Include="X" Version="Y" />`，再在各 `.csproj` 中以无版本形式引用。若某包需要局部覆盖版本，则应通过 `PackageReference` 上的 `<Version>` 子元素（如 `Microsoft.EntityFrameworkCore.Design`、`Microsoft.EntityFrameworkCore.Tools` 所示）。

### 3.2 包族版本一致性

同一生态的包在 `Directory.Packages.props` 中被刻意对齐到相同主版本，例如：

- Microsoft.AspNetCore.* / Microsoft.Extensions.* / Microsoft.EntityFrameworkCore.* / System.Security.Cryptography.* 全部为 `10.0.14`。
- DotNetCore.CAP 全家桶（Core/Dashboard/MySql/RabbitMQ/RedisStreams）全部为 `10.0.2`。
- Emgu.CV 系列（含 runtime.windows / runtime.ubuntu-x64）全部为 `4.10.0.5680`。
- SkiaSharp 与 NativeAssets 均为 `3.119.4`。
- Selenium.WebDriver / Selenium.Support 均为 `4.32.0`。

这体现了“同生态包保持主版本一致”的约定，以降低运行时冲突风险。

### 3.3 特殊处理

- **Harmony 提升**：因 `HttpMataki.NET.Auto` 的传递依赖 `Lib.Harmony 2.4.1` 不支持 .NET 10，仓库在 CPM 中显式抬升到 `2.4.3`，并在注释中说明了原因。
- **测试 SDK**：xUnit (`2.9.3`)、coverlet.collector (`10.1.0`)、Microsoft.NET.Test.Sdk (`18.11.0`) 等测试相关包也在 CPM 中统一管理。
- **前端**：`vue/kevin.web.vue/package.json` 使用 `^` 语义化版本范围（如 `"vue": "^3.2.13"`），并由 `package-lock.json` 锁定实际解析出的版本树；构建脚本通过 `vue-cli-service serve/build/lint` 暴露多环境模式（development / pre）。

## 4. 约定与约束

- **约定（描述性）**：
  - 所有 .NET 第三方包版本集中在 `Directory.Packages.props` 一处维护，`.csproj` 中只出现包名。
  - 同一生态（Microsoft.*、DotNetCore.CAP.*、Emgu.CV.*、SkiaSharp.*、Selenium.*）的包主版本保持一致。
  - 前端依赖使用 npm 语义化版本范围，并通过 `package-lock.json` 提交锁文件。
- **约束（有强制力来源）**：
  - `ManagePackageVersionsCentrally=true` 会强制要求 `PackageReference` 不带版本号，否则构建失败（MSBuild 行为）。
  - `CentralPackageTransitivePinningEnabled=true` 会强制所有传递依赖的版本与 CPM 中声明的版本对齐，防止下游包引入不同版本的传递依赖。
- **未发现**：
  - 无 `nuget.config`、`GlobalPackagesFolder`、私有 NuGet 源或 `GOPRIVATE` 类配置。
  - 无 vendored 第三方源码。
  - 无自动化升级工具（如 Dependabot、Renovate）配置文件。
