## 1. 构建系统总览

本项目采用 **多工程 .NET Solution（NetCoreKevin.sln）+ Docker 多阶段镜像** 的混合构建方式，后端以 ASP.NET Core 9.0 Web API 为主，前端为独立的 Vue 3 SPA。整个仓库没有 Makefile、CI YAML 或 Azure DevOps/GitHub Actions 等流水线文件，构建入口集中在 Visual Studio Solution 与 Dockerfile。

- 解决方案：`NetCoreKevin.sln`，定义 `App` / `Kevin` / `Test` / `Module` 四个 Solution Folder，并显式列出约 45 个 `.csproj` 项目，统一在 `Debug|Any CPU` 与 `Release|Any CPU` 两种配置下构建。
- 运行时目标：所有后端项目均基于 `net9.0`（见 `App.WebApiMcp/App.WebApi.Mcp.csproj` 中的 `<TargetFramework>net9.0</TargetFramework>`），Dockerfile 同样使用 `mcr.microsoft.com/dotnet/aspnet:9.0` 与 `dotnet/sdk:9.0`。
- 前端：位于 `vue/kevin.web.vue/`，通过 `@vue/cli-service`（Vue CLI 5）提供 `serve` / `build` / `lint` 脚本，支持 `development` 与 `pre` 两个环境模式（`.env.development`、`.env.pre`）。

## 3. 构建架构与约定

### 3.1 后端分层与模块组织
- 业务应用层 `App/`：按 Domain → Application → RepositorieRps → WebApi 四层划分，WebApi 是唯一的启动项目（entry point）。
- 核心框架层 `Kevin/`：拆分为 Domain、Application、RepositorieRps、EntityFrameworkCore、Web.Basics 以及大量 `kevin.Module/*` 子模块（如 `Kevin.Common`、`Kevin.Cache`、`Kevin.RabbitMQ`、`Kevin.SignalR`、`Kevin.RAG`、`Kevin.Hangfire`、`Kevin.Permission`、`Kevin.log4Net`、`Kevin.SnowflakeId`、`Kevin.Versioning.Swagger` 等），每个模块都是独立 `.csproj` 并通过 `ServiceCollectionExtensions` 暴露扩展方法注册到 DI。
- 共享层 `Kevin/kevin.Share/`：存放跨领域 DTO、枚举、接口与基础类型，被多个模块引用。
- 测试层 `Test/`：包含单元测试 `Kevin.Unit.Tests`、集成测试 `Kvin.Integration.Tests` 与共享基础设施 `Testing.Shared`。

### 3.2 Docker 多阶段构建流程
`App/WebApi/Dockerfile` 定义了三个阶段：
1. `base`：基于 `aspnet:9.0`，设置 `ASPNETCORE_URLS=http://+:8080`，暴露 8080 端口。
2. `build`：基于 `dotnet/sdk:9.0`，先 `COPY` 全部相关 `.csproj` 文件再 `dotnet restore --disable-parallel`，然后 `COPY . .` 并 `dotnet build -c $BUILD_CONFIGURATION`。
3. `publish`：对 `App.WebApi.csproj` 执行 `dotnet publish -c $BUILD_CONFIGURATION -o /app/publish /p:UseAppHost=false`。
4. `final`：从 `publish` 阶段复制产物，ENTRYPOINT 为 `dotnet App.WebApi.dll`。

该 Dockerfile 显式列举了 30+ 个被引用的 `.csproj` 路径，因此新增模块时必须同步更新 Dockerfile 的 COPY 列表，否则镜像构建会失败。

### 3.3 前端构建
- 使用 `vue-cli-service build` 生成静态资源；`build:dev` 与 `build:pre` 分别对应不同 `.env.*` 环境变量。
- ESLint 通过 `eslint-config` 内联在 `package.json` 中，继承 `plugin:vue/vue3-essential` 与 `eslint:recommended`。
- 浏览器兼容策略由 `browserslist` 指定（>1%、last 2 versions、not ie 11）。

### 3.4 版本与配置
- 无全局版本号管理脚本；前端 `package.json` 固定为 `0.1.0`。
- 运行环境通过 `appsettings.{Development|Test}.json` 与 `ASPNETCORE_ENVIRONMENT` 区分；Docker 镜像强制监听 8080 端口。
- EF Core 迁移位于 `Kevin/Kevin.EntityFrameworkCore/Migrations/`，以时间戳命名（如 `20260731075430_初始化字段.cs`）。

## 4. 约定与约束

- **单一入口**：只有 `App/WebApi` 和 `App/WebApiMcp` 两个 Web 项目可直接运行；其他项目均为类库。
- **Solution 驱动构建**：所有后端构建必须通过 `NetCoreKevin.sln` 或显式指定 `.csproj` 路径进行；不存在 `Directory.Build.props` 等集中 MSBuild 配置。
- **Docker 构建需维护 COPY 清单**：新增 `kevin.Module/*` 下的新模块时，必须在 `App/WebApi/Dockerfile` 的 `COPY *.csproj` 块中添加对应行，否则 `dotnet restore` 会报找不到项目。
- **端口约定**：生产镜像固定监听 `8080`，通过 `ENV ASPNETCORE_URLS=http://+:8080` 强制覆盖默认 80。
- **前端环境隔离**：开发/预发通过 `--mode development` / `--mode pre` 切换，对应 `.env.development` 与 `.env.pre`。
- **测试工程分离**：单元测试与集成测试各自独立工程，共享 `Test/Testing.Shared` 中的测试基类与属性。
- **无 CI/CD 流水线**：仓库未包含 GitHub Actions、Azure Pipelines、Jenkinsfile 等自动化构建脚本；当前构建主要依赖 Visual Studio / `dotnet` CLI / `docker build` 手动触发。
- **EF Core 迁移即数据库版本**：数据库变更通过 `Migrations/` 下的增量迁移文件管理，无第三方迁移工具脚本。

## 5. 适用性说明

本仓库确实存在完整的构建与发布体系（Solution + Docker + Vue CLI），但属于“本地/容器化构建”范畴，没有企业级 CI/CD 流水线、制品仓库或自动化发布流程，因此整体置信度为 medium。
