## 1. 总体方案

该仓库采用 .NET / ASP.NET Core 架构，错误处理由三层组成：
- **领域层/共享层**：定义业务语义化的异常类型（`FieldValidationException`、`UserFriendlyException`）。
- **应用层/服务层**：在参数校验失败或业务规则不满足时抛出上述异常；对第三方调用（如 OpenAI 兼容接口）使用专用异常 `OpenAIProtocolException`。
- **表现层**：通过 ASP.NET Core 的 `UseExceptionHandler` 中间件 + MVC `IResultFilter` 过滤器，把异常统一转换为 `{ code, IsSuccess, msg, errMsg }` 形式的 JSON 响应。

此外，认证鉴权失败由自定义 `AuthenticationHandler`（`ApiResponseHandler`）直接写回 401/403 JSON。

## 3. 架构与约定

### 3.1 异常类型分层

- **`FieldValidationException`**（`kevin.Domain.Share`）：用于 DTO 内部验证（例如 `AIAppsDto`、`dtoUser`、`dtoFormItem`），构造函数支持 `string.Format` 风格的参数化消息。
- **`UserFriendlyException`**（`Web.Global.Exceptions`）：用于业务层抛出的“用户可读”错误，如“数据不存在或已删除”。
- **`OpenAIProtocolException`**（`Kevin.Application.Services.AI`）：携带 HTTP 状态码、错误类型和错误码，专门用于 OpenAI 兼容 API 的错误传播。
- 其他领域内异常（如 `WxPayException`、`TarException`、`InvalidHeaderException`）属于第三方库封装，未进入全局统一处理。

### 3.2 全局异常捕获与响应

`GlobalError.ErrorEvent` 是唯一的顶层异常入口：
1. 从 `HttpContext.Features.Get<IExceptionHandlerFeature>()` 获取异常。
2. 通过 `Kevin.log4Net.LogHelper<Exception>.logger.Error` 记录日志。
3. 若异常为 `UserFriendlyException` 或 `FieldValidationException`：返回 `code=400, IsSuccess=false, errMsg=<message>`。
4. 否则：构造包含 `path`、`parameter`、`authorization`、`error` 的调试信息对象（当前代码中仅序列化到局部变量，未写入响应体，实际响应仍为默认的 500 JSON）。

### 3.3 结果包装过滤器

`ResultFilter` 实现 `IResultFilter`，对所有控制器结果进行后处理：
- 跳过标记了 `SkipResultFilterAttribute` 的 Controller/Action。
- 递归将返回值中的 `null` string 替换为 `""`、`null` List 替换为空集合（最大递归深度 128）。
- 根据 `Response.StatusCode` 重写返回体：
  - 400 → `{ code: 400, IsSuccess: false, msg: "errmsg", errMsg: ... }`
  - 401 → `{ code: 401, IsSuccess: false, msg: "errmsg", errMsg: "未授权" }`
  - 500 → `{ code: 500, IsSuccess: false, msg: "errmsg", errMsg: "系统内部异常" }`
  - 其他 → `{ code: 200, msg: "success", IsSuccess: true, data: ... }`

### 3.4 认证/鉴权错误

`ApiResponseHandler.HandleChallengeAsync` 和 `HandleForbiddenAsync` 直接设置 `Response.StatusCode = 401/403` 并写入固定 JSON：
```json
{"code": 401, "msg": "errmsg", "errMsg": "很抱歉，您无权访问该接口，请确保已经登录!"}
```
403 同理，提示“权限等级不够”。

### 3.5 OpenAI 协议错误特例

`OpenAICompatibleController` 在 catch 块中捕获 `OpenAIProtocolException`，并通过 `WriteProtocolErrorAsync` 按协议格式返回（而非走通用 ResultFilter），以兼容上游 OpenAI SDK 客户端。

## 4. 约定与约束

- **业务异常必须使用 `UserFriendlyException` 或 `FieldValidationException`**：`GlobalError` 只对这两种类型做 400 降级处理，其他异常一律走 500 分支。
- **DTO 内部校验应抛出 `FieldValidationException`**：仓库中所有 DTO 的 `Validate()` 方法（如 `AIAppsDto`、`dtoUser`、`dtoFormItem`）均遵循此约定。
- **OpenAI 兼容接口错误使用 `OpenAIProtocolException`**：该异常自带 statusCode 字段，由 `OpenAICompatibleController` 单独处理，不走全局统一返回体。
- **鉴权失败由 `ApiResponseHandler` 直接写响应**：绕过 MVC 管道，因此不受 `ResultFilter` 包装。
- **全局异常日志统一通过 `Kevin.log4Net.LogHelper<Exception>.logger.Error`**：`GlobalError.ErrorEvent` 是唯一集中记录点。
- **返回体结构约定**：非流式响应最终形如 `{ code, IsSuccess, msg, errMsg, data }`，由 `ResultFilter` 强制统一。
- **401/403 的 `errMsg` 文案硬编码**：`ApiResponseHandler` 和 `ResultFilter` 中对 401/403 返回固定的中文错误消息，未走配置或资源文件。
- **500 分支的调试信息目前未输出**：`GlobalError.ErrorEvent` 中构造了含 path/parameter/authorization/error 的对象，但只赋值给局部变量 `strContent`，没有写入 response，因此客户端收到的是默认 500 JSON。
