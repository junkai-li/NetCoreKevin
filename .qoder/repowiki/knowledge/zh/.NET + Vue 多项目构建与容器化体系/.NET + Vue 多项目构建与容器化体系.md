## 1. 使用的系统与工具

- **后端**：基于 .NET 10 的 ASP.NET Core Web API，使用 Visual Studio Solution (`NetCoreKevin.sln`) 管理 30+ 个 `.csproj` 项目。
- **前端**：Vue 3 + Vue CLI (`vue-cli-service`)，通过 `package.json` 中的 `serve`/`build`/`lint` 脚本驱动。
- **包管理**：NuGet 中央包版本管理（Central Package Management），由根目录 `Directory.Packages.props` 统一维护所有第三方包版本，并启用 `CentralPackageTransitivePinningEnabled` 锁定传递依赖。
- **容器化**：Docker 多阶段构建。后端镜像位于 `App/WebApi/Dockerfile`，前端镜像位于 `vue/kevin.web.vue/Dockerfile`。
- **编排**：`docker-compose.yml` 统一编排 MySQL、Redis、Qdrant、RabbitMQ（可选）、API、Web 六类服务。
- **测试**：xUnit + AutoFixture + FluentAssertions，测试项目为 `Test/Kevin.Web.Test` 和 `Test/Kvin.Integration.Tests`。
- **数据库迁移**：EF Core + MySql，通过环境变量 `DB_AUTO_MIGRATE=true` 在启动时自动执行迁移。

仓库中未发现 Makefile / build.sh / CI pipeline 文件；本地开发以 `dotnet build`、`dotnet publish`、`npm run build` 以及 `docker compose up -d --build` 为主。

## 2. 关键文件

- `NetCoreKevin.sln` — 解决方案入口，定义 App / Kevin / Test / Module 四个顶层分组及全部子项目。
- `Directory.Packages.props` — NuGet 包版本集中管控，包含 ~90 个包的版本声明。
- `App/WebApi/Dockerfile` — 后端多阶段 Docker 构建：SDK 还原 → 发布 → aspnet:10.0 运行镜像。
- `vue/kevin.web.vue/Dockerfile` — Node 20 构建 Vue 产物后由 nginx:1.27-alpine 托管。
- `vue/kevin.web.vue/package.json` — 前端构建脚本与依赖声明。
- `docker-compose.yml` — 一键编排 MySQL 8.0、Redis 7-alpine、Qdrant、RabbitMQ (profile mq)、API、Web。
- `App/WebApi/appsettings*.json` — 运行时配置（Development/Test/Release）。
- `App/WebApi/web.config` — IIS 部署配置。
- `App/WebApi/Properties/PublishProfiles/FolderProfile.pubxml` — VS Folder Profile 发布配置。

## 3. 架构与约定

### 3.1 解决方案结构
`sln` 将项目按业务域分为四层：
- `App/` — 业务应用层（Domain/Application/RepositorieRps/Share/WebApi/WebApiMcp）。
- `Kevin/` — 通用模块库（Domain、Application、EntityFrameworkCore、Web.Basics、RepositorieRps 以及 kevin.Module 下的 20+ 可插拔模块如 Cache、Cap、Hangfire、SignalR、RAG、SMS、Email、Consul、Permission、Jwt、SnowflakeId 等）。
- `Test/` — 单元测试与集成测试。
- `vue/kevin.web.vue/` — 独立的前端工程。

每个 csproj 均输出 Debug/Release 两种配置，并在 sln 中显式绑定 `Debug|Any CPU`、`Debug|x64`、`Debug|x86`、`Release|Any CPU`、`Release|x64`、`Release|x86` 六种组合。

### 3.2 包版本策略
`Directory.Packages.props` 设置 `ManagePackageVersionsCentrally=true` 与 `CentralPackageTransitivePinningEnabled=true`，所有 csproj 中的 `<PackageReference>` 只写包名不写版本，版本变更集中在该文件一处修改。注释明确说明“避免传递依赖取最低版本导致的漏洞告警”。

### 3.3 后端构建流水线（Dockerfile）
- **base 阶段**：`mcr.microsoft.com/dotnet/aspnet:10.0`，安装 `libfontconfig1` 以满足 SkiaSharp 原生依赖，暴露 8080 端口，强制 `ASPNETCORE_URLS=http://+:8080`。
- **build 阶段**：`mcr.microsoft.com/dotnet/sdk:10.0`，先 COPY 所有 csproj 与 `Directory.Packages.props` 再 `dotnet restore`，利用缓存加速；随后 `COPY . .` 全量源码并 `dotnet publish -c $BUILD_CONFIGURATION -o /app/publish /p:UseAppHost=false`。
- **final 阶段**：从 base 复制 publish 产物，创建 `/app/Log` 与 `/app/KevinFlies` 目录并以 `$APP_UID` 非 root 用户运行，ENTRYPOINT 为 `dotnet App.WebApi.dll`。
- 注释强调“新增/删除项目时必须同步维护这份清单”，即 Dockerfile 内显式 COPY 的 csproj 列表必须与 sln 保持同步。

### 3.4 前端构建流水线
- 开发：`npm run serve` / `serve:dev` / `serve:pre`，对应 `development` 与 `pre` 两个 mode。
- 生产：`npm run build` / `build:dev` / `build:pre`，由 `vue-cli-service build` 产出静态资源到 `dist/`。
- Docker 构建：Node 20 Alpine 镜像，默认 npm 源为 `https://registry.npmmirror.com`，可通过 `NPM_REGISTRY` 覆盖；`VUE_APP_API_BASE_URL` 留空表示同源部署，由 Nginx 反向代理到 api 容器。

### 3.5 编排与部署
`docker-compose.yml` 定义了 6 个服务：
- `mysql`：MySQL 8.0，字符集 utf8mb4，时区 +08:00，`max_allowed_packet=64M`，健康检查使用 `mysqladmin ping`。
- `redis`：Redis 7-alpine，开启 AOF，密码通过 `${REDIS_PASSWORD}` 注入。
- `qdrant`：向量数据库，HTTP 6333 / gRPC 6334。
- `api`：.NET WebApi，连接 mysql、redis、qdrant，支持 `DB_AUTO_MIGRATE` 控制 EF 迁移，RabbitMQ 通过 `profiles: ["mq"]` 按需启用。
- `web`：Vue 构建产物 + Nginx，反向代理 `/api` 到 api 容器。
- `rabbitmq`：仅 `--profile mq` 时启动。

所有外部端口通过 `.env` 变量覆盖（`MYSQL_PORT`、`REDIS_PORT`、`WEB_PORT`、`API_PORT`、`RABBITMQ_PORT` 等），默认避开本机常用端口（3306/6379/8080）以避免冲突。

### 3.6 环境配置约定
- 后端通过 `ASPNETCORE_ENVIRONMENT` 区分 Development / Test / 空值（空值即正式环境读取 `appsettings.json`），compose 中刻意不设置该环境变量。
- 前端通过 `--mode development` / `--mode pre` 切换不同 `.env.*` 配置文件。
- RabbitMQ 仅在 `docker compose --profile mq up -d` 时启动，api 的 `depends_on.rabbitmq.required=false` 保证未启用 profile 时不阻塞启动。

## 4. 约定与约束

- **包版本集中管控**：`Directory.Packages.props` 中 `ManagePackageVersionsCentrally=true` 且 `CentralPackageTransitivePinningEnabled=true`，所有 csproj 不得直接指定版本号（由 Central Package Management 强制）。[来源：`Directory.Packages.props` 第 3-8 行]
- **Dockerfile 项目清单需同步**：`App/WebApi/Dockerfile` 中显式 COPY 的 csproj 列表必须与 `NetCoreKevin.sln` 保持一致，否则 `dotnet restore` 找不到项目。[来源：`App/WebApi/Dockerfile` 第 22-25 行注释]
- **SkiaSharp 原生依赖**：基础镜像必须安装 `libfontconfig1`，否则 SkiaSharp 初始化失败并在 GC finalizer 线程崩溃进程。[来源：`App/WebApi/Dockerfile` 第 7-11 行注释]
- **API 监听端口固定 8080**：通过 `ENV ASPNETCORE_URLS=http://+:8080` 强制，对外由反向代理或端口映射暴露。[来源：`App/WebApi/Dockerfile` 第 13 行]
- **运行用户非 root**：最终镜像以 `$APP_UID` 用户运行，日志与上传目录 `/app/Log`、`/app/KevinFlies` 需在构建阶段创建。[来源：`App/WebApi/Dockerfile` 第 73-78 行]
- **前端 npm 源默认国内镜像**：`NPM_REGISTRY=https://registry.npmmirror.com`，可通过 build arg 覆盖为官方源。[来源：`vue/kevin.web.vue/Dockerfile` 第 12-13 行]
- **前端构建堆内存**：`NODE_OPTIONS=--max-old-space-size=4096`，因 vue-cli 打包较吃内存。[来源：`vue/kevin.web.vue/Dockerfile` 第 9-10 行]
- **数据库自动迁移开关**：`DB_AUTO_MIGRATE` 环境变量控制启动时是否执行 EF Core 迁移（首次建表 + 种子数据，升级增量迁移）。[来源：`docker-compose.yml` 第 129-132 行]
- **RabbitMQ 可选组件**：通过 `profiles: ["mq"]` 控制，默认不启动；api 的 depends_on 标记 `required: false`。[来源：`docker-compose.yml` 第 181-201 行]
- **端口避让约定**：compose 注释说明宿主机端口默认避开本机常用端口（MySQL 3306 / Redis 6379 / API 9901），避免与本地已安装服务冲突。[来源：`docker-compose.yml` 第 17-19 行注释]
- **Solution 平台矩阵**：sln 全局定义 Debug/Release × AnyCPU/x64/x86 六种组合，所有项目均映射到这些组合。[来源：`NetCoreKevin.sln` 第 97-104 行]

未发现仓库级 CI/CD 配置文件（无 `.github/workflows`、`.gitlab-ci.yml`、`azure-pipelines.yml`、Makefile、build.sh 等），构建与发布主要依赖 Visual Studio / `dotnet` CLI / `docker compose` 本地执行。
