模块以经典四层架构拆分为独立 csproj 项目，形成单向依赖：WebApi → Application → Domain ← RepositorieRps，AppShare 作为跨层共享 DTO。
- WebApi（入口层）：Program.cs 通过 `WebApplication.CreateBuilder` 构建宿主，注册 Kevin.log4Net 日志、`AddControllers`、全局异常处理、`UseKevin` 中间件，并通过扩展方法 `ConfigServies` 完成服务装配；Controllers/v1、v2 下按版本号划分 API。
- Application（应用服务层）：Services/v1 下的 Service 继承 `BaseService`，实现 Domain 中定义的 `I*Service` 接口，通过构造函数注入仓储接口完成用例编排。
- Domain（领域层）：Entities 定义实体（继承 `CUD_User`），Interfaces/Repositorie 与 Interfaces/Services 分别声明仓储与服务契约，作为应用与仓储之间的稳定边界。
- RepositorieRps（仓储实现层）：Repositories/v1 中的 *Rp 继承通用 `Repository<T, TId>` 并实现对应接口，由 ModuleInitializer 通过 `IocHelper.BatchAddScopeds<IBaseRepository>` 批量注册。
- AppShare（共享 DTO 层）：Dtos/v1 存放跨层共享的数据传输对象。
各层通过各自的 `ModuleInitializer : IModuleInitializer` 暴露初始化逻辑，由上层统一调用完成 DI 注册。配置集中在 appsettings.json（含数据库、Redis、Hangfire、JWT、Consul、文件存储、AI 模型等），并通过环境配置文件覆盖。
